加水印与GIF生成逻辑

一、批量加水印逻辑

1. 选择图片文件夹
   - 扫描所选文件夹中的图片文件。
   - 支持常见图片格式，例如 jpg、jpeg、png、bmp、gif、webp、tiff 等。
   - 处理结果输出到原文件夹下的 Watermarked_Images 目录，不覆盖原图。

2. 水印参数
   - 水印文本：支持普通文字，也支持 {exif_date} 占位符。
   - 字体大小：可固定，也可开启多尺寸适配。
   - 透明度：0 到 100。
   - 颜色：用户选择 RGB 颜色。
   - 位置：左上角、右上角、左下角、右下角、中心。
   - 高对比度模式：根据水印所在区域的亮度自动选黑色或白色。

3. 单张图片处理流程
   - 使用 Pillow 打开图片。
   - 使用 EXIF 方向信息修正图片方向，避免手机照片旋转错误。
   - 如果水印文本包含 {exif_date}，读取图片 EXIF 拍摄时间并替换；没有拍摄时间则替换为 N/A。
   - 图片转换为 RGBA，创建同尺寸透明水印层。
   - 根据文本内容选择字体：包含中文时优先使用中文字体，否则使用英文字体。
   - 如果开启多尺寸适配：
     - 以图片宽度的约 80% 作为目标水印宽度。
     - 在最小字体和最大字体范围内用二分查找计算合适字体大小。
   - 计算文字边界框，得到水印宽度和高度。
   - 根据用户选择的位置计算水印左上角坐标。
   - 如果开启高对比度模式：
     - 裁剪水印将要覆盖的图片区域。
     - 计算该区域平均亮度。
     - 背景亮则用黑色水印，背景暗则用白色水印。
   - 按透明度把文字绘制到水印层。
   - 将原图和水印层进行 alpha 合成。

4. 保存逻辑
   - 输出文件名保持原文件名。
   - JPEG/JPG 不支持透明通道，保存前会铺白底并转为 RGB，质量默认 95。
   - PNG 保留透明通道。
   - WEBP 按 WEBP 保存。
   - 其他格式优先尝试按原格式保存，失败时降级保存为 PNG。

5. 批处理控制
   - 后台线程逐张处理，避免界面完全阻塞。
   - 每处理一张图片更新状态和进度。
   - 支持停止处理：循环中检查停止标记，用户停止后退出后续处理。
   - 处理结束后统计成功数量和失败数量。


二、GIF 生成逻辑

1. 选择图片文件夹
   - 扫描所选文件夹中的图片文件。
   - 图片按文件名排序后作为 GIF 帧顺序。
   - 至少需要 2 张图片才能生成 GIF。
   - 处理结果输出到原文件夹下的 _gif 目录。

2. GIF 参数
   - 帧延迟 delay：每帧显示时间，单位毫秒。
   - 循环次数 repeat：0 表示无限循环。
   - 图片质量 quality：用于控制颜色量化质量。
   - 输出宽度 width。
   - 输出高度 height。
   - 是否保持宽高比 keep_ratio。

3. 单帧处理流程
   - 使用 Pillow 打开图片。
   - 如果保持宽高比：
     - 将图片缩放到目标宽高范围内。
     - 创建一张目标尺寸的白色 RGB 画布。
     - 将缩放后的图片居中粘贴到白色画布上。
   - 如果不保持宽高比：
     - 直接强制 resize 到目标宽高。
   - 将处理后的图片转为 P 模式调色板图像。
   - 调色板使用自适应颜色，最多 256 色。
   - 把该帧加入 GIF 帧列表。

4. GIF 编码与保存
   - 使用第一帧作为主图。
   - 其余帧通过 append_images 追加。
   - save_all=True 表示保存多帧。
   - duration 使用用户设置的帧延迟。
   - loop 使用用户设置的循环次数，0 为无限循环。
   - optimize=True 开启 Pillow 的 GIF 优化。
   - 输出文件名格式通常为 animated_gif_年月日_时分秒.gif。

5. 批处理控制
   - 后台线程逐张处理图片帧。
   - 每处理一张图片更新状态和进度。
   - 支持停止生成：循环中检查停止标记。
   - 生成过程中会注意内存压力，图片过多或过大时需要控制尺寸和数量。


三、保留这个逻辑时的实现建议

1. 加水印和 GIF 都适合保留为独立 core 函数。
2. GUI 只负责收集参数、选择文件夹、显示进度，不要把图像处理细节写死在界面层。
3. 输出目录和文件名规则应保持稳定：
   - 水印：Watermarked_Images
   - GIF：_gif
4. 对大图片批处理时，优先降低预览和缩略图的加载成本，不要在界面线程中打开大图。
5. 真正处理图片时再读取完整图片，列表展示阶段只读取必要信息。
